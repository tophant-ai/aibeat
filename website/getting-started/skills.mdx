# Promptbeat skills

Promptbeat v0.2 is available from the [official GitHub Release](https://github.com/tophant-ai/aibeat/releases/tag/v0.2), and every full package includes the five Skills described below.

Promptbeat skills are agent playbooks for common product workflows: getting started,
connecting coding agents, choosing risk content, running a first evaluation, and
debugging failed runs.

They do not add new Promptbeat CLI commands. They teach your coding agent how to
choose an existing package example, distinguish project configs from generated
Promptfoo configs, run the right command, and explain the resulting artifacts.

## Download

Use either source:

| Source | When to use it |
| --- | --- |
| Release package | Download [Promptbeat v0.2](https://github.com/tophant-ai/aibeat/releases/tag/v0.2) and use its bundled `promptbeat-skills/` directory. |
| Repository checkout | Use the `promptbeat-skills/` directory in this repository. |

The public skill set includes:

| Skill | Purpose |
| --- | --- |
| `promptbeat-getting-started` | Route a new user to the right package example and first command path. |
| `promptbeat-connect-coding-agent` | Wire Codex, Claude Code, OpenCode, or OpenClaw style coding-agent targets. |
| `promptbeat-run-quick-eval` | Pick the right validate, generate, run, eval, or report command. |
| `promptbeat-select-risk-pack` | Choose scenarios, seeds, dataset subscriptions, or a small smoke scope. |
| `promptbeat-debug-run` | Diagnose config, provider, runtime, artifact, and report failures. |

## Load

Copy the whole skill directory, including `SKILL.md` and any `references/` directory.
These commands install all five public skills.

Claude Code:

```bash
mkdir -p ~/.claude/skills
for skill in promptbeat-skills/promptbeat-*; do
  [ -d "$skill" ] && cp -R "$skill" ~/.claude/skills/
done
```

Codex CLI:

```bash
mkdir -p ~/.codex/skills
for skill in promptbeat-skills/promptbeat-*; do
  [ -d "$skill" ] && cp -R "$skill" ~/.codex/skills/
done
```

OpenCode:

```bash
mkdir -p ~/.config/opencode/skills
for skill in promptbeat-skills/promptbeat-*; do
  [ -d "$skill" ] && cp -R "$skill" ~/.config/opencode/skills/
done
```

On Windows PowerShell, for example with Codex CLI:

```powershell
New-Item -ItemType Directory -Force "$HOME\.codex\skills" | Out-Null
Get-ChildItem .\promptbeat-skills -Directory -Filter 'promptbeat-*' |
  Copy-Item -Destination "$HOME\.codex\skills" -Recurse -Force
```

Replace `.codex\skills` with `.claude\skills` for Claude Code.

Use a project-local skill directory instead when your runtime supports one and the
Promptbeat guidance should apply only to that workspace.

## Ask the agent

Start a fresh agent session after installation. Ask for an outcome in natural
language and include the package path, target type, or error when you know it.
You can also mention a skill by name to force that workflow.

| Example request | Expected skill | Expected help |
| --- | --- | --- |
| “I unpacked Promptbeat in `/opt/promptbeat`. Help me run my first LLM safety check.” | `promptbeat-getting-started` | Select an example, check required environment variables, give the first commands, and identify the report path. |
| “Connect this Codex workspace as a target and preserve trace evidence.” | `promptbeat-connect-coding-agent` | Check runtime, workspace, sandbox, credentials, provider wiring, and trace capture. |
| “Validate this config, run five cases, and show me the report.” | `promptbeat-run-quick-eval` | Select the correct validate, generate, run, eval, or report path for the input type. |
| “Choose a small authorization and prompt-injection smoke scope.” | `promptbeat-select-risk-pack` | Reuse a packaged scenario or subscription and preview five generated cases. |
| “Diagnose `working_dir does not exist` without changing credentials.” | `promptbeat-debug-run` | Locate the failing boundary and propose the smallest safe fix. |

The agent runs commands only when its runtime and your approval policy permit it.
Otherwise, it should return copyable commands and explain their outputs.

## Complete walkthrough: package to report

This walkthrough uses the packaged `examples/bootstrap/` project. The response
wording may vary; check the commands, paths, cost boundary, and artifacts.

### 1. Choose the path

Ask:

```text
Promptbeat is unpacked at /opt/promptbeat. Use promptbeat-getting-started to help
me test a normal LLM. Inspect first and do not make paid model calls yet.
```

Expected response:

```text
This is the normal-LLM path. I’ll work from /opt/promptbeat and use
examples/bootstrap/promptbeat.yaml. I’ll check the package and provider variables,
then run validate, which does not make model calls.
```

The agent should stay in the release package and keep secrets out of chat and YAML.

### 2. Prepare providers

Ask the agent to show a placeholder-only environment template and explain the three
roles. It should keep the real values local:

```bash
export ATTACKER_MODEL_NAME="openai:gpt-4o"
export ATTACKER_BASE_URL="https://api.openai.com/v1"
export ATTACKER_API_KEY="<set-locally>"
export JUDGE_MODEL_NAME="openai:gpt-4o"
export JUDGE_BASE_URL="$ATTACKER_BASE_URL"
export JUDGE_API_KEY="$ATTACKER_API_KEY"
export TARGET_MODEL_NAME="openai:gpt-4o-mini"
export TARGET_BASE_URL="$ATTACKER_BASE_URL"
export TARGET_API_KEY="$ATTACKER_API_KEY"
```

Change model names and the endpoint for your OpenAI-compatible provider.

### 3. Validate without model calls

Ask:

```text
Validate the bootstrap project. If execution is not allowed, give me the exact
command and explain its expected output.
```

Expected command:

```bash
cd /opt/promptbeat
./bin/promptbeat validate --config examples/bootstrap/promptbeat.yaml
```

The agent should report whether validation passed and identify missing paths or
variables. It should not claim that the target was tested.

### 4. Preview five cases

Ask:

```text
Use promptbeat-select-risk-pack. Keep the bootstrap scenarios, generate five cases
under artifacts/bootstrap-preview, and do not call the target. Tell me first whether
generation can call the attacker model.
```

Expected response and command:

```text
Generation does not call the target, but it may call the configured attacker model
and incur provider cost. I’ll reuse the packaged scenarios.
```

```bash
./bin/promptbeat generate \
  --config examples/bootstrap/promptbeat.yaml \
  --count 5 \
  --output artifacts/bootstrap-preview/generated_cases.json
```

Review that JSON before approving target execution.

### 5. Run and find the report

Ask:

```text
The five cases are approved. Use promptbeat-run-quick-eval to run the bootstrap
pipeline with TUI progress. Keep outputs under artifacts/bootstrap and report the
real paths without exposing credentials.
```

Expected command:

```bash
./bin/promptbeat pipeline run \
  --config examples/bootstrap/promptbeat.yaml \
  --output-dir artifacts/bootstrap \
  --progress tui
```

The agent should check the exit status and artifact files before reporting success,
then point you to `artifacts/bootstrap/report.html` and summarize the run.

### 6. Recover from a failure

Ask:

```text
Use promptbeat-debug-run. Classify this as a config, path, provider, Promptfoo,
target runtime, parsing, or report failure. Preserve artifacts and do not rotate
credentials unless the evidence shows authentication failed.

<redacted error>
```

The response should cite evidence, propose the smallest reversible fix, and continue
the same workflow after the fix.

### Done means

- Commands came from the release package root.
- Secrets stayed in environment variables.
- Validation ran before model execution.
- You reviewed a small generated sample and understood its cost boundary.
- The target ran only after approval.
- The agent verified and reported existing artifacts.
- `artifacts/bootstrap/report.html` opens successfully.

## Short conversation

```text
User: I unpacked Promptbeat at /opt/promptbeat. Help me test a normal LLM.
Agent: This is the normal-LLM path. I’ll use the packaged llm-basic example.
User: Generate five cases first so I can review them before calling the target.
Agent: I’ll preview them under artifacts/ using promptbeat-select-risk-pack.
User: They look right. Run the evaluation and find report.html.
Agent: I’ll use promptbeat-run-quick-eval and report the resulting artifact paths.
```

## Verify

Start a fresh agent session after copying the files, then ask:

```text
I downloaded Promptbeat. Help me run the examples/bootstrap evaluation and find the report.
```

The expected response should:

- Use `promptbeat-getting-started` or `promptbeat-run-quick-eval`.
- Tell you to run commands from the release package root.
- Use `examples/bootstrap/promptbeat.yaml`.
- Point the result to an `artifacts/` report path.

If the agent suggests source-only commands or paths that are not in the package,
reload the skill directory and include your package root in the next question.

If automatic selection does not happen, use the exact skill name:

```text
Use promptbeat-debug-run to diagnose this error: <error with secrets removed>.
```

To update, copy the directories from a newer release over the installed copies and
start a new session. To disable a skill, remove only its directory from the runtime's
skills folder.
