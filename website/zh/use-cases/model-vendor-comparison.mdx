# 模型与供应商对比

**触发词：** "选型"、"替换供应商"、"哪个模型对我们更安全？"

只有问题固定、只换目标时，比较才成立。

## 让比较成立的规则

1. **同一组候选**给每个目标——生成一次，跑多次。
2. **同一批 Judge**——版本钉死在所有运行上。
3. **同一批 Scenario 与 risk 类型**——不要按供应商挑题。
4. **同一角色**——不要拿生成模型跟目标 Agent 比。
5. **Agent 目标同一环境**——沙箱、工具、审批策略保持不变。

## 推荐路径

<Steps>
  <Step title="先写清决策">
    比较会改变什么？模型 API 选型、Coding Agent 供应商，还是 RAG 后端。先写决策，套件才聚焦。
  </Step>
  <Step title="冻结生成">
    候选只生成一次。存下 `generated_cases.json`，每个供应商复用。
  </Step>
  <Step title="每个目标用相同配置形态跑">
    只差 provider / 模型 id / 端点。其余共享。
  </Step>
  <Step title="成对 diff + 矩阵">
    深度复审用成对 diff；覆盖率与各风险 ASR 用矩阵。
  </Step>
  <Step title="报告里标清角色">
    明确写出生成、Judge、目标版本，读者才不会混角色。
  </Step>
</Steps>

## 决策包里放什么

| Artifact | 为什么 |
|---|---|
| 矩阵：风险 × 目标 × 判定分布 | 管理层视图 |
| 前两名候选的成对 diff | 工程深度 |
| 每类风险的 Finding 样例 | 让数字可信 |
| 成本 / 延迟备注 | 不是安全本身，但常是同一决策的一部分 |

## 常见错误

- 按供应商分别重新生成攻击（每人考不同的卷）
- 给偏好供应商用更强 Judge
- 不把能力类别分开就拿对话模型跟 Agent 比
- 选型对象是 Agent 却省略 Agentbeat
