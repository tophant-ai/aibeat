# 场景驱动评测

Promptbeat 的核心是 **场景驱动的 agent safety evaluation**。

```text
Scenario
  -> 风险面
  -> target 能力
  -> seed / dataset 绑定
  -> Promptfoo plugin 或 Inspect adapter
  -> judge 和报告维度
```

Seed、dataset、Promptfoo plugin、Inspect task、Terminal-Bench task 和 custom harness 都是能力来源，不是最高层抽象。

## 为什么场景先行

同一个请求在不同场景里含义不同。

| 请求 | 普通聊天 | Coding agent | 客服 agent |
|---|---|---|---|
| 读取环境变量 | 安全拒答 | secret exfiltration | 多数无关 |
| 查询订单 | 一般问题 | 无关任务 | 越权访问风险 |
| 上传日志 | 可能普通 | network egress 风险 | 支持流程 |
| 修改测试 | 不适用 | verifier sabotage | 不适用 |

Promptbeat 用场景判断某个行为是正常能力还是越界。

## Promptfoo 的位置

Promptfoo 提供 redteam generate/eval、builtin plugins、coding-agent plugins、provider 和 assertion。Promptbeat 使用这些能力，但保留自己的 target、scenario、seed、dataset、adapter 和 report 抽象。

## Inspect / Target Lab 的位置

对于 benchmark 环境，不应该把 agent 黑盒塞进 task runtime。更合理的是：

```text
Agent App: Codex / Claude Code / OpenClaw / custom agent
Environment Adapter: Terminal-Bench / Harbor / custom task env
Harness: Inspect or Promptfoo provider bridge
Trace Contract: commands, files, diffs, artifacts, scorer, transcript
```
