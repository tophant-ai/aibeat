# 多模型检查

Promptbeat 应该把模型角色讲清楚。一次运行里，可以用一个模型生成攻击，用另一个模型或规则做 judge，再把同一批 case 跑到多个 target agent 上做比较。

```text
generator model -> generated probes
judge model / assertions -> verdicts
same probes -> Codex / Claude Code / OpenClaw / custom agent
report -> 按 target、risk、dataset 比较
```

## 模型角色

| 角色 | 作用 | 示例配置 |
|---|---|---|
| Generator | 把 seed 扩写成攻击 case。 | `openai:openai/gpt-5.5` |
| Target | 被测真实应用。 | `openai:codex-sdk`、CLI adapter、custom provider |
| Judge | 判断 target 是否触发场景失败。 | Promptfoo assertion、模型评分 rubric、trace scorer |
| Baseline | 用来对比的已知 target。 | 当前 Codex broad report |

不要混淆角色。Generator model 不能直接和 target agent 比；judge model 也应该独立记录版本。

## Cross-target 矩阵

同一批 generated case 应该跑到每个 target 上。

| Target | Provider / adapter | Environment | Report dimension |
|---|---|---|---|
| Codex | `openai:codex-sdk` | local workspace / sandbox | 已验证 baseline |
| Claude Code | CLI adapter 或 Inspect solver | Target Lab runtime | 规划中的 coding-agent 比较 |
| OpenClaw | CLI adapter 或 Inspect solver | Target Lab runtime | 规划中的 coding-agent 比较 |
| Internal agent | custom provider 或 script | enterprise harness | 私有策略和工具行为 |

## Cross-generator 矩阵

当你担心攻击生成能力太弱时，使用这个矩阵。

| Generator set | 适用场景 |
|---|---|
| 单个强默认 generator | 快速 regression，成本稳定。 |
| 两个独立 generator | 发现 prompt 风格盲区。 |
| Dataset-direct + generated probes | 对比直接数据集拒答与对抗探索。 |
| 手写 seed + Promptfoo plugins | 同时保留人工意图和内置攻击策略。 |

## Judge 可靠性检查

正式报告应该记录 verdict 如何产生。

- Assertion id 或 rubric version。
- 使用模型评分时，记录 judge model 和 provider version。
- 对 command、file write、network event、artifact 使用 trace scorer。
- 保留代表性 pass / fail 样例供人工 review。
- 启用多个 judge 时，记录 disagreement cases。

## 最小可用比较

```text
1 个 scenario
3 个 risk types
20-50 个 generated probes
2 个 target agents
1 套稳定 judge
1 份 normalized report
```

这足够观察不同 target 在 secret handling、sandbox boundary、network egress、prompt injection 等风险上的差异，同时控制成本和 review 工作量。
