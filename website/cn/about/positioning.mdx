# 产品定位

## 30 秒版本

> Promptbeat 和 Agentbeat 组成一个面向 LLM、RAG 和 Agent 应用的自动化安全评测平台。它从风险场景生成攻击，在客户真实目标上执行，通过标准化判定形成 Finding 和报告，并把高价值样例沉淀为版本化回归基线。
>
> 用于上线前验收和持续回归，不替代运行时防护网关。

## 3 分钟版本

**先讲问题。** 人工红队难规模化。固定题库覆盖有限、跟不上新的攻击表达。模型、Prompt、策略升级后没有稳定基线做对比。

**再讲流程。** 场景配置生成攻击候选；候选跑在真实目标上；标准化 Judge 写 Finding；Finding 晋级为回归数据集。

**再讲结果。** 客户拿到覆盖率、攻击成功率、Finding 证据、模型对比、版本化数据集、以及每次升级后能立刻识别回退的机制。

**再讲边界。** 不是运行时 WAF。不是攻击 Prompt 库。有些 Finding 仍然需要人来复核。

## 典型场景

| 场景 | 触发词 |
|---|---|
| **上线前安全验收** —— 模型或 AI 应用上线前系统化验证主要风险和边界。 | "要上线"、"要验收" |
| **升级后的回归测试** —— 系统 Prompt、模型、知识库或策略变化后检查是否有安全退化。 | "频繁迭代"、"担心回退" |
| **多模型 / 供应商对比** —— 在相同场景和数据集下横向比较多个模型或版本。 | "选型"、"替换供应商" |
| **RAG 与 Agent 边界评估** —— 数据泄露、提示词注入、工具调用、越权。 | "RAG"、"Agent"、"工具调用" |
| **企业安全题库与基线** —— 把历史问题、高价值攻击、困难样例沉淀为版本化内部基线。 | "内部标准"、"基线建设" |

## 平台不做什么

<Info>
  边界要讲清。夸大替代关系，比诚实划边界更快失信。
</Info>

| 不做 | 原因 | 用什么替代 |
|---|---|---|
| …运行时拦截 | 这个平台做评测、不做拦截。实时阻断是另一类产品，另一套 SLO。 | 任何运行时防护网关 / WAF / Guardrail。 |
| …替代专家红队 | 标准化、可复现的 case 可以自动化；复杂业务边界仍需人来判断。 | 关键上线保留 on-call 红队。 |
| …单独交付攻击 Prompt 库 | 攻击生成只是中间环节。完整价值包括真实执行、Judge、证据、数据闭环。 | 使用完整平台。 |

## 与相邻方案的关系

<CardGroup cols={2}>
  <Card title="vs 人工红队" icon="user-plus">
    人工灵活但难规模化、难复现。平台自动化中间可复用部分，让专家把注意力放在高风险 case 上。
  </Card>
  <Card title="vs 固定题库 / 脚本" icon="list-check">
    题库跑得快、便宜，但不自适应、不从执行结果学习。平台闭合了"生成 - 执行 - 数据集演化"这个循环。
  </Card>
  <Card title="vs 运行时防护" icon="shield-halved">
    互补，不是替代。网关在线上拦截，平台在上线前验证、每次升级后回归。一个完整的 AI 安全栈两个都要。
  </Card>
  <Card title="vs LLM eval 框架" icon="microscope">
    传统 eval 只打单条回答的分。平台在真实 Agent 上跑攻击，记录 Agent 做了什么，并把 Finding 晋级到回归集。可以与现有 eval 工具组合使用。
  </Card>
</CardGroup>
