# 报告

一次运行产出 JSON `evaluation_result.json`。报告把它变成可分享的 artifact，供工程、事件响应和管理层使用。

```bash
./bin/promptbeat report \
  --eval-result examples/codex_agent/artifacts/run/evaluation_result.json
```

## 三层

## Finding 的结构

每个 Finding 自包含。

| 段 | 内容 |
|---|---|
| Header | Target、Scenario、Risk 类型、Severity、Judge 版本、Finding id、时间 |
| Input | 被执行的候选，及其血缘（Seed、生成轮次、Rewrite 链） |
| Response | 目标完整响应（含工具调用 metadata） |
| Verdict | `PASS` / `FAIL` / `REVIEW` 加 Judge 依据 |
| Evidence | 抽取的信号：泄露值、越权工具调用、边界引用 |
| Reproduction | 重跑所需的一切：配置版本、数据集版本、Provider 配置 |

Finding 是可分享输出的最小单元。给别人一份 Finding，他就能行动。

## 聚合报告

聚合把 Finding 卷成全景。结构：

- **覆盖率** —— 哪些 Scenario 跑了、每个 Scenario 多少候选、覆盖哪些风险
- **判定分布** —— 按风险、按 Scenario、按 Target 的 PASS / FAIL / REVIEW
- **攻击成功率** —— 每种风险的 FAIL / 总数
- **最严重问题** —— Severity × 出现频次排序的 top-N
- **Finding 列表** —— 所有 FAIL 和 REVIEW，链到完整 Finding

输出格式：

| 格式 | 用途 |
|---|---|
| JSON | 机器可读、工具链集成、自建看板 |
| HTML | 浏览器复审、内部分享、售前 |
| 综合 Markdown | 长文复审含证据摘录、易打印 |

## 对比报告

同一个回归集的两次运行并排——不同模型版本、不同系统 Prompt、不同策略。

| 列 | 含义 |
|---|---|
| 回退 | A 通过、B 失败 |
| 改善 | A 失败、B 通过 |
| 持续 FAIL | 两次都失败——长期风险 |
| 持续 PASS | 两次都通过——确认安全 |
| 判定移位 | PASS ↔ REVIEW 或 REVIEW ↔ FAIL 迁移 |

对比是把"新模型更好"变成可辩护论断的关键。

## Artifact 目录

每次运行都有一个目录，装着重跑所需的一切：

```text
artifacts/
  run/
    evaluation_result.json     # 权威 blob
    findings/                  # 每个 FAIL/REVIEW 一个 JSON
    reports/
      report.html
      report.md
      report.json
    lineage/                   # 候选 → seed → dataset 血缘
    trace/                     # 每候选 Trace（深）
  regression-dataset-v0.3.0/   # 晋级 Finding
```

Artifact 可哈希校验、可版本化；不重跑 target，也可以从 `evaluation_result.json` 重新生成报告。

## 安全分享

<Info>
  报告可能包含真实请求、真实响应和真实 Trace。请当作生产日志处理。
</Info>

- 外部分享前把 Provider 配置里的密钥抹掉
- Finding 泄漏 PII 或业务数据的响应片段要脱敏
- Trace 摘录可能暴露内部端点结构，外部分享前要脱敏
- 售前材料请用种子社区集合里匿名的 Finding，不要用客户运行
