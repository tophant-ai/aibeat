# 从一次性红队测试，到可持续的数据化安全工程

两个产品，覆盖从 Prompt 到 Agent 的完整安全测试链路。**Promptbeat** 面向 LLM、RAG 与 Agent 应用生成并执行攻击，用来发现风险；**Agentbeat** 更进一步：接入被测 Agent，记录每一次工具调用、文件操作和环境变化，为失败的行为形成可复现的证据。

## 为什么需要它

内容安全检查告诉你模型**没说错话**。但它不会告诉你 Agent **做了什么**——读了什么密钥、写了哪张表、外传了什么文件、调用了哪个不该调用的工具。在我们自己的一次真实评测里，某个 Coding Agent 在**5/5**内容安全用例通过的同时，**32 个行为用例中有 11 个失败**：读环境变量、写沙箱外文件、跟随仓库里植入的 prompt injection。

这个差距，就是这个平台要闭合的地方。

<Info>
  Promptbeat 和 Agentbeat 用于**上线前安全验收、升级后持续回归、红队数据资产沉淀**。它们做的是评测，不是运行时拦截——那是另一类产品要解决的问题。
</Info>

## 两个产品怎么配合

Promptbeat 和 Agentbeat 共用同一套 CLI、配置模型、数据集 registry 和报告 schema。实际使用时，用 Promptbeat 发现候选风险，用 Agentbeat 在真实运行环境里验证行为。

```text
scenario + target + seed / dataset
    ↓  Promptbeat  ────────────────────────────→ 发现风险
    ↓  Agentbeat   ────────────────────────────→ 验证行为
    ↓  报告 + 证据 + 数据集晋级                → 回归基线
```
