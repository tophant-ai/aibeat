# Turn one-off red-teaming into a data-driven safety pipeline

Two products for teams that ship AI applications. **Promptbeat** generates and runs attacks against LLMs, RAG apps and agents to surface risks. **Agentbeat** goes one step further: it watches what an agent actually does — every tool call, file change and environment mutation — and produces reproducible evidence for the failures.

## Why this exists

Content-safety checks tell you the model **refused to say something wrong**. They tell you nothing about what the agent **did** in the meantime — read a secret, wrote to a database, exfiltrated a file, called a tool it shouldn't have. In one of our own runs, a coding agent passed **5 out of 5** content-safety cases while quietly failing **11 out of 32** behaviour checks: reading env vars, writing sandbox files, following prompt-injections planted in the repo.

That gap is what this platform closes.

<Info>
  Promptbeat and Agentbeat are for **pre-launch acceptance, post-upgrade regression, and red-team data accumulation**. They evaluate. They do not sit in the request path and block traffic — that's a different class of product.
</Info>

## How it fits together

Promptbeat and Agentbeat share the same CLI, configuration model, dataset registry and report schema. In practice you use Promptbeat to find candidates and Agentbeat to verify them in a real runtime.

```text
scenario + target + seed / dataset
    ↓  Promptbeat  ─────────────────────────────→ find risks
    ↓  Agentbeat   ─────────────────────────────→ verify behaviour
    ↓  reports + evidence + dataset promotion  → regression baseline
```
