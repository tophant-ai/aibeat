Promptbeat ships versioned, hash-verified seed collections through the seed
registry at `registry/seed-registry/v1/`. Each collection is a bundle you pull
with the CLI, so a team can run its first real evaluation without assembling an
attack seed pool by hand.

## Browse the collections

Collection listings, per-collection detail (files, provenance, record schema,
Cisco risk-type and OWASP ASI coverage, review status, known limitations) and
filtering by risk type, language, target type and sensitivity live on the
**Promptbeat seed community site**, which is generated from the registry and
deployed with this docs site under the same origin.

## Pull a collection

Distribution is from the source repository only for now — there is no public
hosted registry URL, so `--registry` points at a local checkout. Run this from
the repository root.

<Info>
  TODO: replace `--registry ./registry/seed-registry/v1` with the public hosted
  registry URL once public distribution is approved. Publication requires
  separate license and release approval.
</Info>

```bash
promptbeat seed pull jailbreak-baseline@0.1.0 \
  --registry ./registry/seed-registry/v1 \
  --output-dir ./.promptbeat/seeds/jailbreak-baseline/0.1.0
```

Then point a scenario at the downloaded file:

```yaml
seeds:
  files:
    - ./.promptbeat/seeds/jailbreak-baseline/0.1.0/seeds.jsonl
```

Both collections are `staging` and carry `controlled` sensitivity: they contain
working attack prompts. Handle the downloaded `seeds.jsonl` the way you would
handle any other offensive test corpus.
